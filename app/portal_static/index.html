讓藍隊在本地用 AI Agent 分析，同時把 Agent 管住。

AI 攻擊又快又多，藍隊需要用 AI 來防禦 AI。但把 AI Agent 放進組織，有兩個擔心：組織的敏感資料被送出去，以及 Agent 不受控、反過來攻擊別人。這套環境就是為了守住這兩件事而設計，每一條都能在這一頁當場驗證。

受治理的 Agent 身上沒有密碼、連不到外網；就算被提示注入騙了，資料也送不出去。

同一個問題，兩個 Agent

左邊是未治理的 Agent：直連資料庫、可以上網、提示裡放著管理密碼。右邊是受治理的 Agent：沒有密碼、只能經過治理閘道、網路被隔離。送出後兩邊同時作答，看誰守住兩條鐵律。

      架構

      整套環境跑在一台主機上，用網路分區把元件隔開。受治理的 Agent 想做任何事，都只能帶著憑證去找治理閘道；閘道驗明身分、查過政策，才代它去存取資料。所有決策都會留下紀錄，交給 Wazuh 偵測，確認違規就由 SOAR 把 Agent 斷線。圖中的燈號是各元件目前的狀態，點選元件可以看說明。

      點選圖中的元件

      每個元件都會說明它是什麼、守住哪一條鐵律、用的是什麼軟體，以及目前是否正常運作。

      • 受治理 Agent 的合法路徑（全部經過治理閘道）
      • 未治理 Agent 的直接連線
      • 被擋下的連線與自動斷線

      一次提問的流程

      1. 藍隊提問。分析人員在這一頁或指令列向 Agent 提出資安分析問題。
      2. Agent 帶憑證找治理閘道。Agent 需要資料或工具時，只能帶著憑證向治理閘道提出請求。
      3. 閘道驗身分、查政策。閘道確認是誰、能用哪些工具、參數有沒有超出範圍，決定允許、拒絕或送人工核准。
      4. 閘道代為存取。允許的請求由閘道代 Agent 去查資料庫、讀文件、查情資；Agent 自己碰不到這些服務。
      5. 全程留紀錄，Wazuh 偵測。每一次決策、每一筆可疑內容都寫成紀錄，由 Wazuh 依規則判斷有沒有注入、越權、外送或對內攻擊。
      6. 違規即斷線。確認違規時，SOAR 呼叫治理閘道撤銷該 Agent 的憑證，Agent 的下一個動作就會被擋下。

      設計理念

      以兩條鐵律為唯一目標

      環境裡的每個元件都要能回答一個問題：它幫忙守住哪一條？敏感資料不外送，屬於資安防護（Security），重點是不被攻擊者騙走；Agent 不攻擊別人，屬於安全約束（Safety），重點是 Agent 自己不會失控。

      零信任：Agent 身上不放任何秘密

      受治理的 Agent 只有一張可以隨時撤銷的憑證。它要的每一筆資料，都由治理閘道驗身分、查政策之後代為取得，對應「憑證 → 治理閘道 → 身分驗證 → 服務」這條存取控制鏈。Agent 被騙了，手上也沒有東西可以洩漏。

      多層防線，任一層擋住就算守住

      網路隔離讓 Agent 連不到內部主機與外網；治理閘道的政策擋下越權與白名單外的請求；工具回傳的內容一律當資料、不當指令，並偵測疑似注入；監控在事後再把關一次，確認違規就斷線。單一層失效不會讓整體失守。

      可以驗證，不靠宣稱

      資料庫與系統提示裡埋了誘餌密碼，受害主機與攻擊者收集站會記下每一次被連線。同一份攻擊考卷分別考未治理與受治理的 Agent，誘餌有沒有外洩、受害主機有沒有被打，都有紀錄可查，可以量化比較。

      本地運作、全部開源

      模型跑在本地的 DGX，組織資料不出門；可以隨時換模型做比較。平台採用 Wazuh、Grafana、PostgreSQL 等開源元件，一鍵部署、不用時可以收起來，方便重現與技術移轉。

      可以做哪些實驗

      考卷分三組：正常工作確認治理不會妨礙分析；鐵律一與鐵律二各有數種攻擊情境。每一題都可以同時讓兩個 Agent 作答，結果會出現在上方的實驗操作台。
