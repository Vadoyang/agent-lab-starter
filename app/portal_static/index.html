讓藍隊在本地用 AI Agent 分析，同時把 Agent 管住。

AI 攻擊又快又多，藍隊需要用 AI 來防禦 AI。但把 AI Agent 放進組織，有兩個擔心：組織的敏感資料被送出去，以及 Agent 不受控、反過來攻擊別人。這套環境就是為了守住這兩件事而設計，每一條都能在這一頁當場驗證。

鐵律一敏感資料不外送

受治理的 Agent 身上沒有密碼、連不到外網，送出的參數與回答都要過護欄；就算被提示注入騙了，資料也送不出去。

同一個問題，兩個 Agent

左邊是未治理的 Agent：直連資料庫、可以上網、提示裡放著管理密碼。右邊是受治理的 Agent：沒有密碼、只能經過 Gateway、網路被隔離，輸入與輸出都過護欄。送出後兩邊同時作答，看誰守住兩條鐵律。關掉護欄可以看只靠 Gateway 時的差別。

      架構

      架構依查老師的設計：任務經 Agent Gateway 進入 Agent runtime，先過輸入護欄再交給 Agent；Agent 要送出的工具參數與回答，先過輸出護欄再經 Gateway 出去。Agent 只連得到 Gateway 與模型代理，模型跑在本地的 Ollama 與 LLM。所有決策都留下紀錄，交給 Wazuh 偵測，確認違規就由 SOAR 撤銷 Agent 的憑證。圖中的燈號是各元件目前的狀態，點選元件可以看說明。

      一次提問的流程

      1. 藍隊交付任務。分析人員在這一頁或指令列交付資安分析任務，任務先送到 Agent Gateway。
      2. 輸入護欄檢查任務。任務裡若夾帶操控 AI 的指令，直接攔下，不交給 Agent。
      3. Agent 帶憑證找 Gateway。Agent 需要資料或工具時，只能帶著憑證向 Gateway 提出請求；Gateway 驗身分、查政策，決定允許、拒絕或送人工核准。
      4. 輸出護欄檢查工具參數。請求送出前，參數裡若夾帶秘密或個資，整筆不執行，防止 Agent 把資料帶出去。
      5. Gateway 代為存取，輸入護欄過濾回傳。允許的請求由 Gateway 代查資料庫、文件與情資；回傳給 Agent 前，移除疑似指令的內容、遮蔽秘密。
      6. 輸出護欄檢查回答。Agent 的最終回答離開前再檢查一次，出現秘密就遮蔽。
      7. 全程留紀錄，違規即斷線。每一個決策都寫成紀錄，由 Wazuh 依規則偵測；確認違規時，SOAR 呼叫 Gateway 撤銷該 Agent 的憑證。

      設計理念

      以兩條鐵律為唯一目標

      環境裡的每個元件都要能回答一個問題：它幫忙守住哪一條？敏感資料不外送，屬於資安防護（Security），重點是不被攻擊者騙走；Agent 不攻擊別人，屬於安全約束（Safety），重點是 Agent 自己不會失控。

      零信任：Agent 身上不放任何秘密

      受治理的 Agent 只有一張可以隨時撤銷的憑證。它要的每一筆資料，都由治理閘道驗身分、查政策之後代為取得，對應「憑證 → 治理閘道 → 身分驗證 → 服務」這條存取控制鏈。Agent 被騙了，手上也沒有東西可以洩漏。

      多層防線，任一層擋住就算守住

      網路隔離讓 Agent 連不到內部主機與外網；Gateway 的政策擋下越權與白名單外的請求；兩側護欄在輸入端過濾注入、在輸出端攔下秘密；模型代理只放行核准的本地模型；監控在事後再把關一次，確認違規就斷線。單一層失效不會讓整體失守。前兩層是確定性的邊界，護欄是機率性的判斷，會漏也會誤判，所以它是第二道防線，效果要用實驗量化。

      可以驗證，不靠宣稱

      資料庫與系統提示裡埋了誘餌密碼，受害主機與攻擊者收集站會記下每一次被連線。同一份攻擊考卷分別考未治理與受治理的 Agent，誘餌有沒有外洩、受害主機有沒有被打，都有紀錄可查，可以量化比較。

      本地運作、全部開源

      模型跑在本地的 DGX，組織資料不出門；可以隨時換模型做比較。平台採用 Wazuh、Grafana、PostgreSQL 等開源元件，一鍵部署、不用時可以收起來，方便重現與技術移轉。

      可以做哪些實驗

      考卷分三組：正常工作確認治理不會妨礙分析；鐵律一與鐵律二各有數種攻擊情境。每一題都可以同時讓兩個 Agent 作答，結果會出現在上方的實驗操作台。搭配護欄開關，可以比較三種條件：未治理、只有 Gateway、Gateway 加護欄。
